Herdr is a terminal workspace manager. It keeps real terminal processes running and adds structure around them.

## Workspace

A workspace is the top-level project container. Use one workspace per repo, task, or investigation.

A workspace owns tabs and panes. Its sidebar state rolls up from the agents inside it, so you can see which project needs attention.

A workspace can also claim a directory, called its pinned path. Set one with `herdr workspace create --path`, `herdr workspace set-path`, or `p` in the goto picker, and it survives restarts. Once a workspace claims `~/code/herdr`, a pane you create whose working directory sits at or under that path moves into a new tab in that workspace, and focus follows it. Split off a shell in `~/code/herdr/src` from an unrelated workspace and it lands where the rest of that repo's work already is.

Herdr matches by path component, so `/ws-worktrees` does not count as living under a pinned `/ws`. When several workspaces claim the same directory, the deepest pin wins: a worktree pinned to `~/code/herdr-issue-42` beats the repo pinned to `~/code`. Herdr resolves symlinks on both sides when the directories exist and compares the paths as written when they do not, so you can pin a repo before you clone it.

Two creation paths route this way: splitting a pane, and creating a tab. The rest stay put on purpose. `herdr workspace create` is a direct instruction to make a workspace, so Herdr never folds the result into another one. Session restore and handoff rebuild the layout you arranged rather than reshuffling it. Popup panes and floating panes are overlays rather than workspace members. A split inside a zoomed tab also stays where you made it.

## Tab

A tab is a layout inside a workspace. Use tabs to separate views like `agents`, `logs`, `server`, or `review`.

Tabs are addressable from the CLI and socket API.

## Pane

A pane is a real terminal. Herdr renders the terminal output, sends input back to the process, and preserves the pane across client detach.

Panes can be split right or down. They can be renamed manually, read from the CLI, sent input, and closed.

## Arrangement

An arrangement is the shape a tab lays its panes out in. Every tab always has exactly one, and a new tab starts in `grid`.

| Arrangement | Layout |
| --- | --- |
| `vertical` | Even columns side by side. |
| `horizontal` | Even rows top to bottom. |
| `grid` | A balanced rectangular grid. |
| `stacked` | One stack. The focused pane fills the tab and the others collapse to single-row title bars above and below it. Click a bar to focus that pane. |

`prefix+]` and `prefix+[` cycle a tab through them. Cycling regenerates the tab from its panes in order, so a full lap returns the layout you started with. Splitting right or down sets the arrangement as well as adding a pane, which means `prefix+v` twice gives three even columns rather than a split nested inside a split. `prefix+enter` adds a pane without changing the arrangement.

Regenerating discards manual sizing. A split border you drag holds until the next pane is created or closed, then the arrangement's even sizing takes over. Arbitrary tree shapes are still reachable through the socket API's `layout.apply`.

## Mouse UI

Herdr is mouse-native. You can click panes, tabs, workspaces, and agents. You can drag split borders, select text, and use right-click menus. Everything below is also reachable by mouse; keyboard bindings are an optional layer.

If you prefer keyboard-only control, or you want Herdr to stop capturing mouse input, disable mouse capture:

```toml
[ui]
mouse_capture = false
```

## Agent

An agent is a process Herdr recognizes inside a pane. Herdr detects agents from foreground processes, screen manifests, and optional integrations.

Agent states are:

| State | Meaning |
| --- | --- |
| `blocked` | The agent needs input, approval, or a decision. |
| `working` | The agent is actively running. |
| `done` | The agent finished and you have not looked at it yet. |
| `idle` | The agent is finished or waiting and has been seen. |
| `unknown` | Herdr cannot confidently classify the state. |

## Session

A session is a persistent Herdr server namespace. The default `herdr` command attaches to the default session.

Named sessions are separate runtime namespaces:

```bash
herdr session list
herdr session attach work
herdr session attach side-project
```

Use workspaces first. Use named sessions when you need completely separate panes, sockets, and persisted runtime state.

## Client and server

By default, Herdr runs as a background server plus one or more attached clients.

The server owns panes and process state. The client is the terminal UI attached to that server.

Detach the client with `ctrl+b q`. The server and agents continue running.

If you want to end the session and stop its panes, stop the server:

```bash
herdr server stop
```

## Modes

Herdr has terminal mode, prefix mode, and navigate mode.

Terminal mode sends keys to the focused pane. Prefix mode waits for one Herdr action after the prefix key. Navigate mode is the persistent workspace navigation surface.

Press the prefix key, default `ctrl+b`, then an action key such as `c` for a new tab or `w` for workspace navigation. New to the prefix idea? See [Keyboard](/docs/keyboard/).
